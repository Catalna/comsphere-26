# DanaTerang Private Evidence Ingestion Plan

> **For agentic workers:** Use `executing-plans` and TDD on the requested `main` branch. Preserve uncommitted changes, use no Docker, and do not commit unless requested.

> **Scope note:** This plan records the earlier evidence-participant download policy. The approved peer-review design at `docs/specs/2026-10-06-peer-review-design.md` supersedes it: only assigned Verifiers may retrieve originals/full OCR; Organizer/Funder views are summary-only.

**Goal:** Let an authorized Organizer upload private program evidence, record its exact-byte SHA-256 and immutable metadata/version, and let authorized campaign participants retrieve the original through the API.

**Architecture:** PostgreSQL stores evidence metadata and version lineage; the original bytes live behind a storage interface. Local Windows development uses a private filesystem root, and cloud staging can use an S3-compatible endpoint. The API validates type/size/signature, hashes exact bytes before storage, and scopes every upload/list/download through Campaign ownership.

**Tech Stack:** Express 5, PostgreSQL `pg`, `pg-mem`, Multer, Node streams/crypto, existing `@dana-terang/proof`, S3-compatible AWS SDK client, Supertest, Playwright.

---

## File Map

- Create `database/migrations/003_evidence.sql` and `.down.sql`: evidence file metadata, raw hash, private storage key, status, version group, and previous-version link.
- Create `backend/src/evidence/uploadValidation.js`: one-file, 10 MiB limit, supported `PDF/JPG/PNG` signatures, filename sanitization, and evidence-type parsing.
- Create `backend/src/storage/localFileStorage.js` and `s3Storage.js`: private local filesystem and S3-compatible `put/read/delete` adapters.
- Create `backend/src/repositories/evidenceRepository.js`, `backend/src/routes/evidence.js`, and `backend/src/evidence/evidenceService.js`: scoped persistence, upload orchestration, and authorized file streaming.
- Create `backend/test/evidence/**`: validation, storage, repository, Supertest authorization, and failure-cleanup cases.
- Modify `backend/src/app.js`, `backend/src/config.js`, `backend/.env.example`, `frontend/app/campaigns/[campaignId]/page.tsx`, and `frontend/tests/test_authenticated_flow.py` for route mount, storage configuration, upload UI, and browser coverage.

## Environment Gates

Tests use a temporary filesystem root and `pg-mem`; no Docker or live cloud storage is used. Native PostgreSQL migration/upload verification remains pending until PostgreSQL is installed and `DATABASE_URL` is configured. S3 staging tests use an injected client; real storage credentials remain in local/staging environment configuration only.
